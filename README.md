**公開サイト:** https://kafka2306.github.io/furutsatotax/

このリポジトリは、ふるさと納税の「自己負担2,000円で収まる寄附上限」を計算します。

## 結論：住民税通知書モードを正準にする

年収から住民税を推定するより、翌年度の住民税通知書に記載された実額を使う方が精度が高いため、公開UIとPython CLIの正準ルートを次の入力に変更しています。

- 税額控除前所得割額
- 調整控除額
- 課税総所得金額
- 所得税との人的控除額の差
- 総所得金額等（所得税基礎控除判定・寄附金30%上限確認用）

ふるさと納税特例控除の20%上限に使う母数は、寄附金控除・住宅ローン控除等を差し引いた後の最終所得割額ではありません。

```text
調整控除後所得割額
= 税額控除前所得割額 - 調整控除額

特例控除上限
= 調整控除後所得割額 × 20%

寄附上限
= 特例控除上限 ÷ 特例控除率 + 2,000円
```

令和8年度住民税（2025年分所得）からは、特例控除率の判定基礎が次のように見直されています。

```text
特例控除率判定基礎
= 課税総所得金額
- 所得税との人的控除額の差
- max(所得税基礎控除額 - 48万円, 0)
```

大阪市公式の令和8年度以降の特例控除率（復興特別所得税反映後）は次の通りです。

| 判定基礎 | 特例控除率 |
|---:|---:|
| 195万円以下 | 84.895% |
| 195万円超330万円以下 | 79.790% |
| 330万円超695万円以下 | 69.580% |
| 695万円超900万円以下 | 66.517% |
| 900万円超1,800万円以下 | 56.307% |
| 1,800万円超4,000万円以下 | 49.160% |
| 4,000万円超 | 44.055% |

## 対応年分

| `tax_year` | 対応する主な住民税年度 | 給与所得控除 | 所得税基礎控除 |
|---:|---|---|---|
| 2024 | 令和7年度 | 令和2〜6年分 | 48万・32万・16万・0円 |
| 2025 | 令和8年度 | 最低65万円を含む令和7年分 | 95万〜58万円の所得帯別特例 |
| 2026 | 令和9年度 | 令和8年分 | 104万・67万・62万円等 |

未対応年度は別年度の税表を流用せずエラーで停止します。公開UIからも、根拠未実装の2027年選択肢を削除しました。

## 今回の監査で修正した致命的な問題

1. **WebとPythonで別の税計算を持ち、Webだけ旧税制のまま**だった問題を修正。ブラウザ用の純粋計算コア `web/tax-core.js` を追加し、公開UIはそこだけを呼びます。
2. **2025/2026を選んでもWebが2024年の給与所得控除・基礎控除を使う**問題を修正。
3. **令和6年以前の給与所得控除55万円を `max(55万円, 収入×40%)` と誤計算**していた問題を修正。
4. **所得税率境界を `>` で判定し、195万・330万・695万円ちょうどで一段低い税率になる**問題を `>=` に修正。
5. **ふるさと納税特例控除率を所得税の限界税率から直接逆算**していた問題を修正。住民税の公式特例控除率表と、令和8年度以降の基礎控除補正を使います。
6. **住民税課税所得×10%をそのまま20%上限の母数にしていた**問題を修正。調整控除後所得割額を使います。
7. **寄附金控除後の最終所得割額を上限計算に使える設計**を廃止し、通知書の税額控除前所得割額を正準入力にしました。
8. **株式等の申告分離課税を総合課税へ黙って加算**する経路を禁止。簡易モードではfail-closeし、通知書モードへ誘導します。
9. **事業赤字を0円へ黙って丸める**処理を禁止。損失・繰越控除を含むケースは実課税標準または通知書モードを使います。
10. **配偶者控除を「配偶者給与103万円以下なら一律38万円」と自動計算**する旧Webロジックを撤去。令和7年分からの123万円基準、本人所得帯、配偶者特別控除、住民税との差を一律推定しません。
11. **社会保険料を給与の15%としてreadonlyで強制入力**する処理を撤去。実額を使える設計に変更しました。
12. **2027年を未実装のままUIで選べる**状態を廃止。
13. **Web計算をCIで検証していなかった**問題を修正。Node回帰テストを追加し、Pages公開前にもPython/JS双方のテストを必須化しました。

## 公開UI

公開サイトでは2つのモードがあります。

### 1. 住民税通知書モード（推奨）

実際の住民税通知書を入力します。株式等の申告分離課税がある場合でも、所得割20%上限の母数を「税額控除前所得割額」から取得できます。

ただし、大阪市公式も、課税山林所得・課税退職所得・課税の特例が適用される所得がある場合は特例控除率が通常表と異なる場合があるとしています。その場合は自治体確認値を「特例控除率の上書き」に入力してください。

### 2. 収入から概算

給与収入、その他の総合課税所得、住民税の所得控除から概算します。

次の場合は誤差ではなく制度上の分岐があるため、簡易モードを停止します。

- 株式等の申告分離課税
- 分離課税所得
- 事業赤字・損失通算・繰越控除を簡易入力だけで再現しようとする場合

### 統計分布から合成例を入れる

収入概算モードでは、個人由来の「年収○○万円の人」という少数の例ではなく、国税庁「令和6年分 民間給与実態統計調査」第3表の給与階級をそのまま使った例示カタログを表示します。

- 対象: 1年を通じて勤務した給与所得者・男女計 51,365,699人
- 給与階級: 100万円以下〜2,500万円超の14区分を全て保持
- `population` と `share_pct`: 国税庁公表値
- `example_salary_yen`: 各階級を試すための合成代表値。特定個人の給与ではない
- 税務条件: 「追加控除なし」「控除30万円」「控除80万円」「その他所得30万円」等の合成条件。人口頻度を表さない
- 分離課税ありの例は、簡易モードが安全停止することを確認するテストケース

正準データは `web/data/synthetic-income-profiles.json` です。旧来の個人的に見えやすい6個のYAML例はmainから削除しました。

統計の一次資料:

- 国税庁「令和6年分 民間給与実態統計調査」  
  https://www.nta.go.jp/publication/statistics/kokuzeicho/minkan2024/minkan.htm
- 国税庁「第3表 給与階級別の総括表」  
  https://www.nta.go.jp/publication/statistics/kokuzeicho/minkan2024/pdf/R06_03.pdf

**プライバシー境界:** 給与階級の人数・構成比以外の例示入力は合成値であり、リポジトリ所有者を含む特定個人の所得・税務情報を表しません。

## Python CLI

住民税通知書モードでは、次のキーへ自分の通知書・申告資料の実額を入力します。READMEには個人データと誤読される具体的な所得例を固定しません。

```yaml
tax_year: 2025
total_income: <総所得金額等の実額>
resident_taxable_general_income: <課税総所得金額の実額>
resident_income_levy_before_tax_credits: <税額控除前所得割額の実額>
resident_adjustment_deduction: <調整控除額の実額>
human_deduction_difference: <人的控除額の差の実額>
```

実行:

```bash
python scripts/calc_furusato.py input.yaml --tax-year 2025
```

収入推計モードも残していますが、通知書がある場合は通知書モードを優先してください。

## 限界

本ツールは税務申告ソフトを代替しません。特に、山林所得・退職所得・土地建物・株式等の課税特例が特例控除率判定へ影響するケースは、通知書の所得割額だけでは通常表の率まで確定できないことがあります。

一方、**「税額控除前所得割額から調整控除だけを差し引いた額の20%を特例控除上限とする」部分は、通知書実額を使うことで年収推定より強い根拠を持ちます。**

本ツールは税務助言ではありません。最終確認は国税庁・自治体・税理士等の一次情報で行ってください。
